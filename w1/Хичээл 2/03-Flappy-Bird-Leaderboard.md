# Апп 3 — Flappy Bird + Leaderboard

> **Түвшин:** Дунд-ахисан · **Хугацаа:** 3 хичээл (~4.5 цаг) · **Database:** Firebase Firestore

---

## Зорилго

- Тоглоомын мөчлөг (game loop) гэж юу вэ
- Таталцал, хурд, хурдатгал — энгийн физик
- Мөргөлдөөн шалгах (collision detection)
- Дэлгэцийн төлөв (эхлэх / тоглох / дуусах)
- Утсанд хадгалах (AsyncStorage) vs үүлэнд хадгалах (Firestore) — ялгаа
- Leaderboard буюу эрэмбэлсэн жагсаалт

---

## Firestore бэлтгэл

Апп 2-т үүсгэсэн Firebase төслөө **дахин ашиглана** — шинээр үүсгэх шаардлагагүй. Шинэ цуглуулга нэмэхэд ямар ч тохиргоо хийхгүй: эхний баримт бичигдэх үед Firestore цуглуулгыг **өөрөө үүсгэдэг.**

Шинэ цуглуулга: **`flappyScores`**

| Талбар       | Төрөл  | Жишээ                |
| ------------ | ------ | -------------------- |
| `playerName` | string | `"Бат"`              |
| `score`      | number | `27`                 |
| `createdAt`  | time   | `serverTimestamp()`  |

> **Заах цэг — Index гэж юу вэ?** Номын сангийн каталог гэж зүйрлэ: 10,000 ном дундаас нэгийг олоход бүх номыг харах уу, эсвэл цагаан толгойн жагсаалтаас харах уу?
>
> Firestore нэг талбарын index-ийг **өөрөө** үүсгэдэг — тиймээс `orderBy('score', 'desc')` шууд ажиллана. Харин **хоёр талбар хослуулбал** (жишээ нь `where` + өөр талбараар `orderBy`) "composite index хэрэгтэй" гэсэн алдаа гарна. Тэр алдаанд **шууд линк** байдаг — дарж Create дарахад л үүснэ. Сурагчдад энэ алдааг **зориуд гаргуулж** үзүүлэх нь сайхан хичээл.

> **Багшид:** Rules-ээ Апп 2-ын үед аль хэдийн нээсэн (`allow read, write: if true`). Шинэ цуглуулга тэр дүрэмд автоматаар багтана.

```

- Дэлгэцийн зүүн талд жижиг дүрс (шувуу) байна.

- Баруун талаас хоолой (дээд + доод хэсэг, дунд нь нүхтэй) тогтмол хурдаар

- Оноог дэлгэцийн дээд хэсэгт том үсгээр харуул.

Кодыг тодорхой хэсгүүдэд хуваа:
1) физик (шувууны байрлал, хурд)
2) хоолой үүсгэгч ба хөдөлгөгч
```

## Ярилцах сэдэв (заавал орох)

**"Оноог утсанд хадгалах уу, серверт хадгалах уу?"**

Сурагчдаас асуу:

1. Утсандаа хадгалсан оноог найз чинь харж чадах уу? (Үгүй)
2. Утсаа солиход оноо чинь яах вэ? (Алдагдана)
3. Тэгвэл яагаад бид AsyncStorage-г бас ашиглаж байна вэ? (Интернэтгүй үед ажиллана, хурдан)

Хариулт: **хоёуланг нь ашигладаг**. Дотоод нь хурдан, үүл нь хуваалцах боломжтой. Бодит апп бүр ингэж хийдэг.

**"Хэн нэгэн хуурч оноогоо 999999 болгож болох уу?"**

Болно — учир нь бид оноог утсанд тооцоод серверт зүгээр илгээж байна. Бодит тоглоомууд серверт нь дахин шалгадаг. Энэ бол хамгаалалт (security) гэдэг сэдвийн эхлэл.

## Түгээмэл алдаа

| Алдаа | Шийдэл |
|---|---|
| Тоглоом маш удаан / гацна | `setInterval` олон удаа үүссэн. Цэвэрлэх (`clearInterval`) хийгээгүй |
| Шувуу мөргөөгүй ч дуусна | Мөргөлдөөний хайрцаг хэт том. Дүрсээс жижиг тавь |
| Оноо 2 удаа нэмэгдэнэ | Нэг хоолой давахад дахин тоолж байна. Хоолой бүрд `passed` тэмдэг тавь |
| Утас болгон дээр өөр хурдтай | Хугацаанаас (delta time) хамааруулж тооцоолоогүй |
| Топ 10 хоосон | Rules нээгээгүй, эсвэл цуглуулгын нэр буруу бичигдсэн (`flappyScores` ↔ `flappy_scores`) |
| "The query requires an index" | Алдааны текст дэх **линкийг дар** → Create index → 1-2 минут хүлээгээд дахин турш |
